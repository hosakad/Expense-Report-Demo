## バグ・動いていない可能性がある機能

### 1. SQLパラメータのタプル化漏れ（実行時エラー）
**場所:** `expense_report_demo.py`

複数箇所でパラメータがタプルではなく文字列や整数で渡されており、`psycopg2` がエラーを起こす可能性がある。

```python
# 問題のある書き方（例）
params = (request.form['id'])   # タプルではなくstr
params = (",".join(id_removed)) # タプルではなくstr

# 正しい書き方
params = (request.form['id'],)
params = (",".join(id_removed),)
```

### 2. ファイルアップロードの部分的な不具合
**場所:** `file_operations.py`, `expense_report_demo.py`

- ファイルサイズの2MB制限がクライアントサイドのJavaScriptのみで実装されており、サーバーサイドでの検証がない
- `delete_file()` 呼び出し前に `receipt_image` が `None` かどうかを確認していない箇所があり、存在しないファイルの削除を試みる可能性がある
- ファイルの拡張子・MIMEタイプのサーバーサイド検証がない

### 3. IN句の動的生成によるSQLインジェクションリスク
**場所:** `expense_report_demo.py`（report_detail処理付近）

```python
# 複数IDを扱うIN句でプレースホルダーを動的結合している
f"where id in(%s)"
```

カンマ区切り文字列をそのまま1つのプレースホルダーに渡す実装は psycopg2 では意図通りに動作しない場合がある。

### 4. DBコネクションのグローバル管理
**場所:** `db_operations.py`

モジュールレベルのグローバル変数でコネクションを1つ保持しているが、コネクション切断後の再接続ロジックが不完全で、長時間運用時にエラーになる可能性がある。

## 改善すべき点（コード品質）

- **テストがない**: ユニットテスト・統合テストが一切存在しない
- **ロギングなし**: `print()` もなく、エラーは例外を握り潰している箇所がある
- **型アノテーションなし**: 全関数に型ヒントがない
- **`STATUS_APRROVED` のタイポ**: constants.py, JSON, DBデータが全て同一タイポのため修正には全箇所の一括対応が必要
- **Pendo APIキーが2種類ある理由が不明**: `PENDO_API_KEY` と `PENDO_API_KEY_2` の使い分けがコメントなし
